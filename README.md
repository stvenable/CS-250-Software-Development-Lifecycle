# CS-250-Software-Development-Lifecycle

**1. How do I interpret user needs and implement them into a program? How does creating “user stories” help with this?**
   To interpret user needs, analyzing user's desired outcomes to establish clear system inputs and technical boundaries will help build the program in small, iterative slices. Creating user stories helps this process by translating complex or vague requirements into a simple, standardized "As a... I want to... So that..." template that keeps the development team focused on end-user value.
   
2. How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?
   Pair programming is an incredibly valuable Agile process that I plan to incorporate in my future software development work. I learned a lot about electronics while earning my associates degree in Electronics Engineering Technology, but I learned so much more on the job working with coworkers. This hands-on learning approach aligns with how I plan to build software, as I aim to focus heavily on continuous, team-driven communication over isolated development.
   
3. What does it mean to be a good team member in software development?
   If were acting as the Scrum master I would do the following in order to be a good team member. As a Scrum master, I would encourage the team members to build a good rapport with their teammates to strengthen their personal relationships. Sprint Planning would be the first thing I consider when the workday starts. This will help prepare me for the upcoming discussions in today’s daily Scrum meeting. It will also help me protect the team from scope creep and over-committing to certain tasks. As the daily Scrum is coming to a close, I would make sure to go around the room and give everyone a last chance to speak before ending the meeting.
